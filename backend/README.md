# HealthSync — Backend REST API & Database Documentation

HealthSync is an IoT-enabled remote patient health monitoring backend built for college hackathons and local laptop deployment. It ingests telemetry from ESP32 microcontrollers and simulated biomedical feeds, records data into a persistent local SQLite database, performs prototype health status evaluations, manages emergency alerts, and streams realistic Lead II ECG waveforms to the HealthSync dashboard.

---

## Architecture

```
ESP32 + Sensors (DS18B20, Pulse Sensor, AD8232)
       ↓
Wi-Fi (HTTP POST JSON)
       ↓
HealthSync Backend REST API (Node.js + Express on Port 5000)
       ↓
Persistent SQLite Database (database/healthsync.db)
       ↓
HealthSync Dashboard (React + Vite)
```

---

## Hardware & Data Modes

- **DS18B20 Temperature Sensor**: Real biomedical surface probe readings (`dataMode: "HARDWARE"`).
- **Pulse Sensor**: Real optical photoplethysmography sensor for heart rate.
- **AD8232 ECG Module / Simulated ECG**: AD8232 ECG module is physically connected; for the demo, ECG is generated by a continuous Gaussian superposition Lead II synthesizer (`ecgMode: "SIMULATED"`), labeled **"SIMULATED ECG — DEMO DATA"**.
- **SpO2**: MAX30102 is offline; SpO2 is mathematically simulated (`dataMode: "DEMO"`), labeled **"SIMULATED SpO2"**.

## Installation & Setup

### 1. Prerequisites
- **Node.js** v20.0.0 or higher (Node v22+ recommended; uses native `node:sqlite`)
- **npm** v10+

### 2. Install Dependencies
```bash
cd backend
npm install
```

### 3. Database Initialization
The SQLite database file is stored at `backend/database/healthsync.db`.
Initialization is automatic on server startup. If the database is empty, it automatically runs `schema.sql` and seeds:
- Demo Patient: `PATIENT-001` (Demo Patient, 25, Male, Blood Group O+)
- Demo Device: `HEALTHSYNC-ESP32-01` (ONLINE)
- Companion clinical patients: `P-101` to `P-105`

To reset the database at any time, simply delete `backend/database/healthsync.db` and restart the server.

### 4. Start the Backend
```bash
# Production mode
npm start

# Development mode (with auto-restart on file edits)
npm run dev
```

The backend starts at:
```
http://localhost:5000
```

## REST API Endpoints

### 1. System & Health Check

#### `GET /api/health`
Checks server and SQLite database health.
**Response (200 OK):**
```json
{
  "status": "ok",
  "service": "HealthSync Backend REST API",
  "uptimeSeconds": 42,
  "database": "SQLite Connected",
  "timestamp": "2026-09-18T10:00:00.000Z"
}
```

#### `GET /api/system/status`
Returns live KPI metrics for dashboard header:
**Response (200 OK):**
```json
{
  "system": {
    "status": "OPERATIONAL",
    "message": "All Services Operational",
    "activeSensors": 16,
    "uptimeSeconds": 120
  },
  "kpis": {
    "totalPatients": 6,
    "patientsCurrentlyMonitoring": 4,
    "stable": 4,
    "attentionRequired": 1,
    "critical": 0,
    "devicesOnline": 4,
    "totalDevices": 6,
    "unacknowledgedAlerts": 1
  }
}
```

### 2. Patient Management

#### `GET /api/patients`
Returns all registered patients with latest vitals and device assignments.

#### `GET /api/patients/:patientId`
Returns complete profile, notes, and recent telemetry history.

#### `POST /api/patients`
Registers a new patient.
**Request Body:**
```json
{
  "patientId": "PATIENT-002",
  "fullName": "Jane Doe",
  "age": 32,
  "gender": "Female",
  "phone": "9876543210",
  "email": "jane.doe@example.com",
  "address": "Room Cardio 104",
  "emergencyContactName": "John Doe",
  "emergencyContactPhone": "9876543211",
  "bloodGroup": "A+",
  "medicalNotes": "Post-op observation"
}
```
**Response (201 Created):**
```json
{
  "success": true,
  "message": "Patient registered successfully",
  "patient": {
    "patientId": "PATIENT-002",
    "fullName": "Jane Doe",
    "age": 32,
    "gender": "Female",
    "bloodGroup": "A+"
  }
}
```

#### `PUT /api/patients/:patientId`
Updates patient demographic or medical information.

#### `DELETE /api/patients/:patientId`
Safely removes patient registration while preserving historical telemetry logs.

---

### 3. Telemetry & IoT Ingestion

#### `POST /api/iot/telemetry`
Primary ingestion endpoint for ESP32 and telemetry clients.
**Request Body:**
```json
{
  "deviceId": "HEALTHSYNC-ESP32-01",
  "patientId": "PATIENT-001",
  "heartRate": 78,
  "spo2": 98,
  "temperature": 33.2,
  "ecg": 0.42,
  "ecgMode": "SIMULATED",
  "dataMode": "DEMO",
  "status": "STABLE",
  "timestamp": "2026-09-18T10:00:00Z"
}
```
**Response (200 OK):**
```json
{
  "success": true,
  "message": "Telemetry ingested successfully",
  "telemetryId": 142,
  "patientId": "PATIENT-001",
  "deviceId": "HEALTHSYNC-ESP32-01",
  "status": "STABLE",
  "dataMode": "DEMO",
  "ecgMode": "SIMULATED",
  "alertsTriggered": 0,
  "timestamp": "2026-09-18T10:00:00Z"
}
```

#### `GET /api/patients/:patientId/latest`
Returns latest vital readings for specified patient.

#### `GET /api/patients/:patientId/history?limit=100`
Returns chronological array of telemetry records for trend graphing.

### 4. ECG & Demo Simulator

#### `GET /api/demo/ecg?limit=300`
Returns continuous Lead II ECG voltage points (P-Q-R-S-T wave morphology):
```json
[
  { "timestamp": "2026-09-18T10:00:00.010Z", "value": 0.162 },
  { "timestamp": "2026-09-18T10:00:00.020Z", "value": 1.284 },
  { "timestamp": "2026-09-18T10:00:00.030Z", "value": -0.345 }
]
```

#### `GET /api/demo/vitals`
Returns current simulated parameters, smoothing status, and UI labels.

#### `POST /api/demo/mode`
Switches demo scenario with gradual physiologic transitions:
**Request Body:**
```json
{
  "mode": "CRITICAL"
}
```
- **`NORMAL`**: HR 70–85 BPM, SpO2 96–99%, Temp 36.5–37.2°C, Status `STABLE`
- **`ATTENTION`**: HR 100–110 BPM (or <=50), SpO2 91–95%, Temp 38.0–38.5°C, Status `ATTENTION`
- **`CRITICAL`**: HR >= 120 BPM, SpO2 <= 90%, Temp >= 39.0°C, Status `CRITICAL`

### 5. Alerts System

#### `GET /api/alerts`
Returns recent alerts with optional `?acknowledged=false` filter.

#### `POST /api/alerts/:alertId/acknowledge`
Acknowledge an alert:
```json
{
  "acknowledgedBy": "Dr. Sarah Chen, MD"
}
```

---

### 6. Device Management

#### `GET /api/devices`
Returns all registered IoT nodes with connection status (`ONLINE` if active packet received within 60 seconds; otherwise `OFFLINE`).

## ESP32 Telemetry Connection Guide

To connect the physical ESP32 to the backend:
1. Connect ESP32 to the same local Wi-Fi or laptop mobile hotspot.
2. Find the laptop's local IP address (e.g. `192.168.1.100` via `ipconfig`).
3. Send HTTP POST to `http://<laptop-ip>:5000/api/iot/telemetry` with `Content-Type: application/json`.
4. See `esp32/healthsync_esp32.ino` for the complete Arduino sketch.
